## Próximos itens, nesta ordem

1. **Implantação na nuvem:** subir o `notes-server` em `100.64.100.125`, atrás
   de `tura.samirhv.com.br`. O alcance está decidido (ADR-076): nome público,
   certificado ACME, pareamento sem `--allow-private`. O contrato do front —
   `X-Forwarded-Proto`, `Origin` removido, corpo de 16 MiB, `/healthz` atrás do
   portão — está em
   [`docs/SERVER-0.5.md`](../docs/SERVER-0.5.md#co-tenant-deployment-behind-an-existing-site).

   O host, conferido em 16/09/2026: Debian 13 trixie, x86_64, **Apache** com
   mais de oito sites e `certbot --apache` (padrão `-le-ssl.conf`), certbot já
   instalado. `tura.samirhv.com.br` resolve, está atrás do Cloudflare e hoje
   responde 404 do vhost padrão. Nada escuta em 8787 e o `notes-server` não
   está instalado.

   ```bash
   # 1. binário (x86_64, do release minor mais novo — patches não levam anexos)
   curl -LO https://github.com/samirhvbr/tura-notes/releases/download/1.1.0/notes-server-1.1.0-x86_64-linux.tar.gz
   sha256sum -c notes-server-1.1.0-x86_64-linux.tar.gz.sha256
   tar -xzf notes-server-1.1.0-x86_64-linux.tar.gz
   sudo install -m 0755 notes-server /usr/local/bin/notes-server

   # 2. serviço
   sudo useradd --system --home-dir /var/lib/notes-server --shell /usr/sbin/nologin notes
   sudo install -m 0644 server/cotenant/notes-server.service /etc/systemd/system/
   sudo systemctl daemon-reload && sudo systemctl enable --now notes-server
   sudo -u notes NOTES_SERVER_DATA=/var/lib/notes-server notes-server workspace create personal

   # 3. vhost HTTP (só HTTP — ver a armadilha abaixo)
   sudo a2enmod proxy proxy_http headers
   sudo install -m 0644 server/cotenant/apache-tura.conf \
        /etc/apache2/sites-available/tura.samirhv.com.br.conf
   sudo a2ensite tura.samirhv.com.br
   sudo apachectl configtest && sudo systemctl reload apache2

   # 4. certificado — com o registro em DNS-only no Cloudflare durante a emissão
   sudo certbot --apache -d tura.samirhv.com.br
   # religar o proxy do Cloudflare depois, em Full (strict)

   # 5. conferir
   curl https://tura.samirhv.com.br/healthz    # {"status":"ok"}
   ```

   **A armadilha, e ela derruba os outros sites:** não escrever
   `<VirtualHost *:443>` à mão. Um vhost TLS apontando para um certificado que
   ainda não existe faz o Apache se recusar a iniciar, e aí caem samirhv.com.br,
   shvia.org e os outros seis. O `apache-tura.conf` é HTTP puro de propósito;
   quem gera o TLS é o `certbot --apache`, que clona o vhost já com o
   certificado em disco. O nome já
   existe no DNS e ainda responde pelo vhost padrão (Matomo): criar o vhost
   antes de pedir o certificado.
